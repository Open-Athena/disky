# R2 closed-history handoff

Status: implemented for CI review, disabled in every deployed collector, November 8. No receipt bucket, publisher credential or archive deletion has been provisioned. CS3 needs bounded collector metadata as well as the already-live consumer checkpoint.

`dt-cloud access r2-receipt -c gs://oa-r2-usage-data/access/r2/closed.parquet -o tmp/r2-read.json -w tmp/receipt` reads the durable checkpoint back with its GCS generation pinned. It requires a full-history verification marker carried forward by later incremental updates, and records the source/account, checkpoint URI, exact generation, SHA-256 and incorporated per-bucket cursors. Existing checkpoints without the new marker need another full comparison; the external bootstrap report alone does not mint a receipt. The command writes a local review artifact only.

The optional collector `CHECKPOINTS` binding reads one `r2-read.json` in a dedicated private bucket. A receipt for another source, account or checkpoint, a malformed revision/digest, or a cursor behind an existing bound cannot compact history. A missing or unavailable receipt keeps history while collection continues. A passing receipt removes only covered `frozen` references; active/reverification windows and legacy daily aggregates stay. The prior full state is saved under the invocation's `runs/` prefix before the conditional state publication. That recovery copy follows the existing 30-day lifecycle. Two extra binding operations fit OA's conservative subrequest budget (998 of 1,000 at its configured maximum). Deploy the schema-3-aware incremental consumer before enabling the collector binding; preserve the durable checkpoint and its full verification marker across that cutover.

Compaction publishes state schema 3 and explicitly records the omitted bound and checkpoint URI on each bucket. Legacy aggregation rejects it. `access r2-sync` requires the exact checkpoint URI, matching source/account and cursors at least as advanced as every omitted bound before fetching any active inputs; a missing, restored older or different checkpoint fails without replacing the served summary. Full-history verification against compacted state is refused rather than presented as an independent source comparison. No aggregate deletion is implemented by this metadata protocol.

## Concrete transport proposal

After CI and a real receipt readback, the OA collector stack can opt in with `checkpointBucket=oa-r2-read-receipts` and `readCheckpoint=gs://oa-r2-usage-data/access/r2/closed.parquet`. The prepared Pulumi change creates that protected private R2 bucket and its disabled managed domain, and adds `CHECKPOINTS`, `CHECKPOINT_KEY=r2-read.json` and `READ_CHECKPOINT` to the existing collector. Its account and cron stay unchanged. No production index bucket is exposed to the collector. An R2 binding technically grants bucket access; the implementation uses only `get`, and the dedicated bucket contains receipts only.

The job publisher would need a new R2 write credential scoped only to this receipt bucket, stored directly in this deployment's GCP Secret Manager. The source read key and index publisher key are not broadened or copied. Provisioning that credential and the new binding needs Ryan's approval of this concrete plan. Receipt publication follows the durable checkpoint update; it may lag safely. Collector bounds never move backwards, so a stale receipt stalls further trimming. No credential value belongs in this spec, Agent Mail or transcripts.

Aggregate storage retirement is a separate reviewed step: derive the exact unreachable `agg/` keys, preserve a recovery grace, and delete only under an approved receipt-gated policy. This spec does not authorize historical deletion, that policy, IAM changes or a live apply. The existing 621-key cleanup review contains no access-archive aggregates.
